## ۱. چه چیزی دربارهٔ پروژه بررسی شد؟

فروشگاه یک ASP.NET Core MVC/Razor روی .NET 10، EF Core/SQLite و Identity است. nginx فایل استاتیک را تحویل می‌دهد و درخواست برنامه را به Kestrel می‌فرستد. Node فقط برای تولید asset است.

- مسیر درخواست: nginx → middlewareهای فشرده‌سازی/امنیت/نشست/کش → Controller → سرویس/SQLite → Razor.
- خانه: `HomeController`، انتخابگرهای ۸ محصول منتخب و ۸ پیشنهاد، محتوای قابل تنظیم، استوری و payload جداگانه.
- نمایش تصویر: `ProductImageHelper`، `_ProductImageStage` و مشتق LCP؛ تصاویر studio و scene معادل یکدیگر نیستند.
- استایل: شش فایل CSS مبدا؛ باندل کامل سایر صفحات، باندل مخصوص خانه و باندل سبد. معماری نهایی مرحلهٔ ۱۰ استایل کامل خانه را یک‌بار inline می‌کند؛ سایر صفحات باندل کش‌پذیر مستقل دارند.
- تعامل: stories/home با defer؛ حساب/منو/سبد با loader دارای replay کلیک اول؛ modalها و سبد شخصی از endpoint مستقل می‌آیند.
- خرید: واریانت/واحد/تعداد بسته، قیمت تومان در UI و تبدیل به ریال در structured data، سبد session و محاسبهٔ قیمت سرور، حداقل سفارش و تخفیف پلکانی.
- داده‌های ماندگار: SQLite، تصاویر آپلودی، App_Data و تنظیم production باید در انتشار حفظ شوند.
- SEO: canonical، sitemap، JSON-LD، llms/ai؛ امتیاز مصنوعی، review یا رتبهٔ ساختگی مجاز نیست.
- مدیریت/Editorial: controllerها، محتوا، انتشار و سرویس‌های نگهداری دارای اثر نوشتن هستند؛ برای اندازه‌گیری frontend اجرا نشوند.

[نقشهٔ معماری و ریسک‌های پیشین](../PROJECT-MAP.fa.md) و [نمایهٔ فایل‌های منبع](project-source-index.json) مکمل این دفترچه‌اند.
نمایه شامل مسیر، تعداد خط، hash و نام typeهاست؛ فهرست‌برداری را به معنی ممیزی انسانی خط‌به‌خط همهٔ کدها یا اثبات بی‌نقص‌بودن پروژه معرفی نمی‌کنیم.
فایل‌های vendor نیز ممکن است در شمار نمایه باشند. تنظیمات/اسرار و دیتای مشتری در این نمایه منتشر نشده‌اند.

### Waterfall و بخش‌های دیگر

۱. دو `/` با ۳۰۷ پیش از HTML نهایی: headers و Location وجود ندارند؛ هیچ redirect امنیتی کورکورانه حذف نشود.
۲. فونت ۱۰۹KB: فایل دست‌نخورده حفظ شد؛ preload و CSS یک URL fingerprintدار مصرف می‌کنند تا درخواست/کش تکراری نداشته باشند.
۳. CSS حدود ۳۷٫۵KB فشرده: bundle minify می‌شود، critical inline و کامل async فوری است؛ هیچ timeout چندثانیه‌ای برای استایل نداریم.
۴. درخواست‌های تصاویر `01-lcp.webp`: نام مشترک فایل، شناسهٔ محصول نیست. مسیرهای فهرست cache معلوم‌اند، اما نگاشت دقیق تک‌تک ردیف‌های هم‌نام Waterfall به آن‌ها بدون HAR قطعی نیست.
۵. دو لوگوی PNG/WebP: هدر و favicon از یک WebP موجود با fallback اصلی استفاده می‌کنند؛ اصل PNG حذف نشده است.
۶. Stories.json و اسکریپت‌های استوری/خانه باید حاضر بمانند؛ حذف request برای بهبود ظاهری نمره پذیرفته نیست.
۷. Panel/Modal: پاسخ شخصی‌اند؛ انتقال آن‌ها به cache عمومی مجاز نیست. اولین کلیک و بازیابی از خطای دانلود تست می‌شود.
۸. visitor canceled: به‌تنهایی علت افت نمره یا خرابی analytics ثابت نمی‌شود؛ خروج از صفحه و lifecycle درخواست باید دیده شوند.
۹. CPU حدود ۵۷٫۶٪ و حافظه حدود ۴۲۰MB: مشاهدات آن اجرا، نه ممیزی مستقل امتیازدار.
۱۰. CrUX داده ندارد؛ INP اندازه‌گیری نشده و TBT جایگزین عدد INP نیست.
۱۱. ویدئو کامل، passed/no-impactها و alerts مالک در transcript نیستند؛ برایشان خروجی ساختگی نساخته‌ایم.
۱۲. تاریخچهٔ تقریبی LCP ۲٫۵ و CLS .03 نشان‌دهندهٔ regression است؛ علت یا commit آن بدون تطبیق deployment معلوم نیست.

## ۴. اصلاحات این مرحله

- هیرو: حذف lazy از تصاویر اسلایدهای بالای صفحه؛ تصویر اول همان preload با hash فایل، انتخابگر preload مطابق محصولات دارای تصویر در view.
- CSS: minify بدون purge selectorها؛ اضافه‌شدن قواعد featureهای ابتدای صفحه به critical با حفظ cascade.
- انیمیشن‌ها: progress هیرو با transform و تجدید در هر تعویض؛ زمینهٔ متحرک promo روی لایهٔ جدا با همان گرادیان و زمان‌بندی.
- dual کارت: progress و glow با native transform animation، بدون تغییر متغیر ریشه در هر فریم؛ مدیریت صحیح مجموعهٔ کارت‌های دیده‌شده و شروع مجدد پس از بازگشت.
- DOM: اشتراک paint definitions سه خانوادهٔ SVG؛ مسیرها، رنگ‌ها، سایه‌ها و آیکون‌های قابل مشاهده حفظ شدند.
- کش asset: fingerprint تصاویر مشترک/هیرو، فونت و لوگو؛ preload فونت با URL داخل CSS یکسان است؛ glyph/فایل فونت تغییر نکرد.
- loader: شکست دانلود script قابلیت retry دارد و script موفق دوباره تزریق نمی‌شود؛ کلیک اول replay می‌شود.
- سبد: syntax نامعتبر `?.textContent =` در cart-human مانع اجرای کل فایل بود؛ با انتساب شرطی معتبر اصلاح شد.

هیچ تصویر منبعی در این مرحله حذف یا بازفشرده نشده است. تعداد ۸+۸، استوری‌ها، محتوای متنی و افکت‌های موجود برای نمره پنهان/غیرفعال نشده‌اند. pause استاندارد انیمیشن خارج viewport/تب برای برگشت کاربر قابل ادامه است.

۷. تست تازهٔ GT با Seattle/دستگاه/اتصال یکسان؛ A ابتدا، >۹۵ سپس. هر metric و محدودیت با شاهد گزارش شود.
۸. اگر محدودیت شبکه/دامنه مانع بود، وضعیت را باز بگذار؛ local Lighthouse را به‌جای GT یا Structure اعلام نکن.

## ۷. شواهد اجرا و محدودیت عملیاتی

[نتایج اعتبارسنجی این مرحله](validation.json) شامل نسخه و تنظیمات Lighthouse محلی، مقادیر قبل/بعد و روش تست است.
مبنای محلی قبل از تغییرات این مرحله قبلاً Performance=۹۸ داشت؛ این نشان نمی‌دهد VPS همین کد را اجرا می‌کند.
نتیجهٔ محلی مقایسهٔ معتبر Seattle نیست؛ workload هم‌زمان و تغییرات طبیعی مرورگر می‌توانند اعداد زمان را جابه‌جا کنند.

شبکهٔ محیط مقصد production و GTmetrix را با ۴۰۳ مسدود می‌کند؛ هیچ deploy یا retest تازهٔ GT انجام‌شده اعلام نشده است. Google/Bing و انجمن‌های عمومی نیز در پژوهش پیشین قابل دسترسی نبودند؛ بحث‌های GitHub و کدهای عمومی خوانده شدند.
از ۶۵۸ms TTFB گزارش، ۲۱۵ms backend است؛ همهٔ تأخیر را به فاصلهٔ Seattle تا ایران نسبت نمی‌دهیم. بدون تست جدید، سقف فیزیکی LCP یا تضمین اثر CDN قابل تعیین نیست.

## ۹. تکمیل بهینه‌سازی کد با حفظ ظاهر — ۳۱ اکتبر ۲۰۲۶

در این مرحله، طبق آخرین دستور علی، اعمال روی VPS از محدوده خارج شد. اصلاح کد، ساخت Release، تست مرورگر و اندازه‌گیری محلی ادامه یافت. نتیجهٔ واقعی GTmetrix هنوز به تست روی نسخهٔ منتشرشده وابسته است؛ هیچ Grade یا Structure تازه‌ای از اعداد Lighthouse ساخته نشده است.

### تغییرات تکمیلی

- تصاویر responsive در خانه، کارت‌ها، گالری محصول، لوگو و آیکون تلفن؛ `srcset` و `sizes` متناسب با کاربرد، پوشش DPR=۱ و ۲ و fallback تصویر اصلی. preload هیرو دقیقاً همان نامزدهای تصویر مصرف‌کننده را دارد؛ تصویر fallback هم‌زمان دوباره دانلود نمی‌شود.
- تولید مشتق‌ها پیش از درخواست کاربر انجام می‌شود. اصل فایل‌ها بازنویسی یا حذف نمی‌شود؛ WebP مشتق lossless است و نامزد بزرگ‌تر از منبع انتخاب نمی‌شود. عکس متحرک تخت نمی‌شود، جهت EXIF و رنگ شفاف حفظ می‌شود، فایل قدیمی بعد از آپلود جدید انتخاب نمی‌شود و نام فایل دارای فاصله/ویرگول در `srcset` درست encode می‌شود.
- CSS خانه و CSS اختصاصی سبد جدا شدند؛ سایر صفحات همچنان باندل کامل دارند. CSS سبد با قصد تعامل دریافت می‌شود و بازشدن سبد منتظر استایل می‌ماند. اولین کلیک منو/ورود/سبد پیش از رسیدن CSS اصلی هم از دست نمی‌رود؛ شکست دریافت CSS یا اسکریپت قابل تکرار است. هیچ تأخیر چندثانیه‌ای عمدی برای فعال‌کردن استایل وجود ندارد.
- دریافت خودکار پنل خصوصی ورود/سبد هنگام صرفاً خواندن خانه حذف شد؛ prefetch بر اساس قصد واقعی تعامل باقی است. خود قابلیت‌ها و محتوایشان حذف نشده‌اند.
- افکت‌های spark با همان گرادیان از حرکت پس‌زمینه به `transform` منتقل شدند؛ CSS بحرانی از استایل واقعی کارت‌ها و بخش‌های بیشتر ساخته می‌شود تا ورود باندل، transition ناخواسته ایجاد نکند. حالت عادی انیمیشن‌ها برقرار است؛ ترجیح reduced-motion کاربر هم رعایت می‌شود.
- هدرهای forwarded فقط از nginx محلی مورد اعتمادند؛ scheme صحیح پیش از HTTPS redirection اعمال می‌شود. این کار جلوی یک نوع حلقهٔ redirect را می‌گیرد؛ علت دو ۳۰۷ گزارش قبلی بدون Locationهای واقعی به آن نسبت داده نشده است.
- تولید سنگین تصویر در staging پیش از توقف سرویس انجام می‌شود؛ خطای این مرحله سرویس سالم را متوقف نمی‌کند. smoke فایل‌های CSS/JS تازه را با MIME واقعی کنترل می‌کند تا پاسخ HTML با وضعیت ۲۰۰ به‌اشتباه فایل سالم تلقی نشود.

### شواهد و پذیرش

[نتایج عددی و شواهد مرحلهٔ دوم](responsive-validation.json)، [نگاشت تمام ۲۱ مورد گزارش به وضعیت این مرحله](optimization-audit-results.csv) و [وضعیت محلی فهرست تجمیعی auditها](local-audit-checklist.csv) ثبت شده‌اند. موردی که در اجرای Lighthouse وجود ندارد با «قبول» جایگزین نشده است؛ فهرست تجمیعی شامل قواعد تاریخی و وابسته به نسخه هم هست.

۷۰ تست ‎.NET، هفت تست انتشار/بازیابی، smoke هر دو Kestrel و nginx، اولین کلیک استوری/منو/ورود/سبد، CSS کند/ناموفق، صفحات عمومی، انتخاب عکس در DPRهای مختلف و حرکت اسلایدها بررسی شدند. مقایسهٔ طراحی در عرض‌های ۳۹۰، ۷۶۸ و ۱۳۶۶ با نسخهٔ قبلی انجام شده؛ حرکت فقط هنگام screenshot مقایسه‌ای ثابت شد، نه در کد production یا اجرای امتیازدهی.

### مواردی که به‌دروغ «بسته» نشده‌اند

- HTTP/2 و CDN نیازمند تنظیم و راستی‌آزمایی زیرساخت‌اند و در این مرحله روی VPS اعمال نشدند. `proxy_http_version 1.1` نام پروتکل سمت مرورگر را تغییر نمی‌دهد.
- زنجیرهٔ ۳۰۷، عناصر سه shift و جزئیات نه long task گزارش قدیمی trace/HAR کامل ندارند. اجرای محلی جدید شاهد رفع همان عنصر production محسوب نمی‌شود.
- DOM هنوز ۱۳۰۵ عنصر دارد. اجزای قابل مشاهده یا امکانات برای رسیدن به حد مصنوعی حذف نشده‌اند.
- coverage اولیه بخشی از CSS مورد استفاده در اسکرول، منو و modal را unused می‌نامد؛ باقی‌ماندهٔ آن بدون اثبات بی‌مصرف‌بودن در تمام حالت‌ها پاک نشده است.
- Grade A و Structure بالای ۹۵ تنها با GTmetrix تازه پس از انتشار قابل تأییدند. نمرهٔ Performance محلی، SEO یا INP واقعی را اثبات نمی‌کند.

نتیجهٔ اجرای نهایی همین مرحله: Lighthouse 12.6.1 / Chrome 154، دسکتاپ با RTT شبیه‌سازی‌شدهٔ ۴۰ms، نرخ ۱۰Mbps و CPU×۱: **Performance=۱۰۰، FCP≈۰٫۳s، LCP≈۰٫۷s، TBT≈۴۰ms، CLS=۰، Speed Index≈۰٫۵s**. ممیزی اندازهٔ تصاویر پاس شد. بار انتقالی این workload محلی حدود ۵۸۴KiB است؛ قبل از اصلاح تصویر/CSS در اجرای محلی مرحلهٔ قبلی حدود ۱۴۴۷KiB بود. این دو حجم را با ۴۱۰KB گزارش production معادل نگیرید. تفاوت بارگذاری تنبل، تصاویر حاضر در viewport و دادهٔ محیط باعث تفاوت workload می‌شود.

هش ۲۴۲ تصویر منبع پیش/پس برابر بود. انتخاب تصویر در ۱۲ حالت عرض/DPR/کاربرد کافی بود؛ مقایسهٔ طراحی در هر سه عرض با اختلاف هندسی کمتر از یک پیکسل CSS، فونت/رنگ یکسان و تعداد محصولات برابر پاس شد. ممیزی non-composited در این اجرا بدون خطا و بدون مورد (`notApplicable`) بود؛ این به معنی خاموش‌کردن انیمیشن‌ها نیست. هنوز سه long task محلی وجود داشت؛ عدد TBT صفر اعلام نشده است.

آخرین بازبینی صفحهٔ محصول، lazy بودن تصویر اول گالری در حالت عکس studio را هم رفع کرد. بستهٔ Release تازه پس از این تغییر ساخته شد؛ smoke و ده مسیر عمومی/گالری/بازیابی اسکریپت/چرخهٔ تصویر دوگانه دوباره پاس شدند. کد و assetهای صفحهٔ خانه بعد از اجرای عددی ثبت‌شده تغییر نکردند. تست مستقل کش nginx هم سیاست‌های مهمان، حساب/سبد/session، Set-Cookie، پاسخ خصوصی و خطاها را پاس کرد.

در localhost ممکن است ممیزی پروتکل Lighthouse امتیاز قبول بدهد؛ این مدرک فعال‌بودن HTTP/2 نیست. پروتکل واقعی این آزمون HTTP/1.1 است و پذیرش HTTP/2 production جدا باقی مانده است.

برای تکرار تست‌های مرورگر، ابتدا روی بستهٔ جدا `--optimize-images` اجرا و سرور آزمایشی را روشن کنید؛ سپس با `BASE_URL` همان محیط، اسکریپت‌های `verify-home-performance.cjs`، `verify-responsive-images.cjs` و `verify-storefront-performance.cjs` را اجرا کنید. تست‌ها نیازمند Playwright و Chromium هستند. تولید مشتق در مسیر تصاویر زنده برای آزمایش لازم نیست.


## ۱۰. گزارش تازهٔ Q5dcQ8tt و اصلاحات بعد از انتشار کاربر

مبنای این مرحله گزارش ارسالی و چهار screenshot علی است: **B، Performance=۸۰، Structure=۹۴، LCP=۱٫۷s، TBT=۲۰۴ms و CLS=۰**. onload برابر ۲٫۹s و Fully Loaded برابر ۳٫۷s است. دریافت مستقل گزارش/هدرهای production از این محیط انجام نشده؛ انتشار روی VPS نیز طبق محدودهٔ تعیین‌شده انجام نشد.

[تمام داده‌های قابل اتکای گزارش، ۲۳ ردیف و ۲۸ درخواست](report-Q5dcQ8tt.json)، [وضعیت تک‌تک ممیزی‌ها و محدودیت‌ها](report-Q5dcQ8tt-audit-results.csv) و [شواهد اجرای نهایی](network-validation-Q5dcQ8tt.json).

### علت‌ها و اصلاحات قطعی کد

- عکس صحنهٔ کارت با اندازهٔ ثابت ۳۸۴px انتخاب می‌شد؛ برخی مشتق‌های lossless از JPEG بزرگ‌تر بودند و انتخاب به JPEG کامل برمی‌گشت. اکنون عکس‌های JPEG مشتق WebP با کیفیت ۹۴ و نام نسخه‌دار `photo-v1` دارند؛ `sizes=auto` همراه fallback متناسب با کارت و نامزدهای ۲۷۲/۵۶۰px، دریافت بیش‌ازحد را کم می‌کند. عکس اصلی دست‌نخورده است؛ مشتق عکس شفاف استودیو و برند همچنان lossless است. مشتق JPEG را lossless معرفی نمی‌کنیم.
- چیدمان ناقص ردیف‌های پایین‌تر پیش از رسیدن CSS می‌توانست باعث انتخاب زودهنگام تصویر بزرگ شود. نسخهٔ نهایی، CSS کامل مخصوص خانه را یک‌بار از ابتدا inline می‌کند و باندل تکراری را دوباره دانلود/اعمال نمی‌کند. fallback خارجی در نبود فایل inline، blocking است. CSS اختصاصی سبد با تعامل دریافت می‌شود و پیش از بازشدن modal آماده است. استایل حساب/ورود و منو حذف نشده است.
- فقط قوانین کامل و مختص صفحات دیگر از باندل خانه کنار گذاشته شدند؛ باندل اصلی آن صفحات کامل مانده است. پاک‌کردن کلاس‌ها صرفاً با coverage یک بار بازکردن خانه انجام نشد.
- فونت همان وزیرمتن با همان محور وزن است؛ پوشش رایج از ۱۱۱۱۵۲ به ۸۵۷۱۲ بایت رسید. نسخهٔ کامل برای حروف دیگر باقی است. محدودهٔ واقعی fallback از cmap استخراج شده تا برای emoji فاقد glyph، فونت کامل بی‌دلیل دریافت نشود. عرض حروف در وزن‌های ۱۰۰/۴۰۰/۷۰۰/۹۰۰ برابر و fallback حروف لاتین توسعه‌یافته در مرورگر بررسی شد. بازتولید اختیاری با `scripts/subset-storefront-font.sh` است؛ deploy به fontTools وابسته نیست.
- دادهٔ استوری از همان مدل SSR به‌صورت JSON امن داخل HTML آمده و یک رفت‌وبرگشت مستقل حذف شده است؛ endpoint قبلی برای fallback و مصرف مستقل باقی است. مسدودبودن یا خراب‌بودن localStorage، استوری را از کار نمی‌اندازد.
- خواندن اجباری اندازهٔ marquee وقتی انیمیشن آن در CSS دسکتاپ اجرا نمی‌شود حذف شد. تغییر عرض نقطه‌های اسلایدر با FLIP و transform نمایش داده می‌شود. گالری دوحالته فقط کارت‌های واقعاً نزدیک viewport را به‌روزرسانی می‌کند؛ blur و چرخهٔ شش‌ثانیه‌ای اصلی حفظ شده‌اند. هیچ مسیر ویژهٔ GT یا تشخیص User-Agent اضافه نشده است.
- مقدار `StageDualCycle=false` در خانهٔ کد پایه پیدا شد و به true برگشت. آزمون قبلی چرخهٔ مستقل، حضور گالری واقعی در SSR خانه را ثابت نمی‌کرد؛ آزمون تازه خود کارت‌های واقعی را الزام می‌کند. عدد محلی ۱۳۰۵ عنصرِ مرحلهٔ قبل معیار مقایسهٔ هم‌قابلیت با گزارش جدید نبود. تعداد DOM نسخهٔ نهایی در اجرای Lighthouse حدود ۱۴۰۳ است و همچنان finding محسوب می‌شود.
- `site.js` هنگام initialization دیرهنگام و pageshow، اسکرول را اجباری صفر می‌کرد؛ این رفتار حذف شد. اسکرول کاربر و بازگشت مرورگر حفظ می‌شوند. اولین کلیک کنترل‌ها، retry فایل‌ها و سبد با CSS کند/ناموفق بررسی شدند.
- انتخاب alias صحنهٔ WebP اصلاح شد؛ alias تازه پشت cache منفی نمی‌ماند و صحنه با عکس استودیو اشتباه نمی‌شود. لوگوی پایین صفحه lazy شد؛ تصاویر خبر، کاور و لوگوی بخش پایانی هم وارد مسیر responsive/fingerprint شدند. LCP هیرو lazy نشده است.

## ۱۱. بازبینی تکمیلی؛ حفظ ظاهر و کاهش کار تکراری

این مرحله پس از `1f01bc1` انجام شد. نتیجهٔ واقعی production همچنان گزارش **Q5dcQ8tt: B / ۸۰ / ۹۴** است؛ هیچ نمرهٔ محلی جایگزین آن نیست. [شواهد قابل بررسی این مرحله](followup-validation-Q5dcQ8tt.json).

- فیلتر قدیمی CSS فقط قواعد تک‌خطی را می‌فهمید. اکنون قواعد کامل و مختص صفحات حساب/آدرس/سفارش/کاتالوگ/محصول، حتی داخل شرط‌های تو‌در‌تو، از باندل خانه جدا می‌شوند. selectorهای مشترک، keyframeها و at-ruleهای ناشناخته حفظ می‌شوند. باندل عمومی و باندل سبد بایت‌به‌بایت برابر نسخهٔ قبل‌اند. شش تست parser شامل رشته، comment، escape و data URL اضافه شد. این کاهش محدود است؛ ادعای حذف تمام CSS گزارش‌شده نداریم.
- برای عرض ۴۲۰، مشتق نسخه‌دار `packed-v1` با WebP **lossless** و تلاش encoder بیشتر ساخته می‌شود. انتخاب فقط وقتی انجام می‌شود که فایل تازه و کوچک‌تر از گزینهٔ معمول و اصل باشد. گزینهٔ معمول و فایل اصلی حذف یا جایگزین نمی‌شوند؛ نبود مشتق جدید fallback سالم دارد. ۶۳ مشتق با مرجع resize‌شده مقایسه شدند: تمام پیکسل‌های RGBA برابر بودند. برای محصول ۰۰۵۶، ۵۳۲۲۲ به ۵۰۳۶۲ بایت؛ برای ۰۰۱۷، ۵۹۴۷۴ به ۵۵۹۵۴ بایت. این اعداد صرفه‌جویی کل صفحه نیستند. تولید اضافه در مرحلهٔ آماده‌سازی انتشار انجام می‌شود و به هر درخواست کاربر تحمیل نمی‌شود.
- countdown فقط بخش تغییرکرده را در DOM می‌نویسد. تست مرورگر پیشروی ثانیه و ارقام فارسی را تأیید می‌کند؛ روز/ساعت/دقیقهٔ ثابت mutation اضافی ندارند. ساعت محصول فریز نشده است.
- بررسی انتشار nginx اکنون Host عمومی، cache HIT مهمان با و بدون کوکی `_mv`، MIME و cache یک‌سالهٔ immutable منابع نسخه‌دار و TTL حداکثر یک‌ساعتهٔ تصویر بدون نسخه را بررسی می‌کند. این بررسی خطای vhost عمومی را که پشت پاسخ ۲۰۰ loopback پنهان بود آشکار می‌کند. برای میزبان دیگر `MS_SMOKE_HOST` تنظیم شود. این smoke مربوط به HTTP فعلی است؛ مهاجرت به HTTPS نیازمند آزمون URL و گواهی همان میزبان خواهد بود.

اصل ۲۴۲ فایل تصویر در بستهٔ آزمایشی با مخزن برابر ماند. تست‌های مرورگر، مقایسهٔ هندسه/فونت/رنگ در سه عرض، تصاویر واقعی در عرض و DPR مختلف، استوری و اولین کلیک منو/سبد/ورود در شواهد ثبت شده‌اند. تست عمومی و strict nginx محلی پاس شدند. انتشار روی VPS در این مرحله انجام نشده است.

### تغییرات منتخب

- nginx پاسخ HTML فشرده‌شدهٔ جریانی Kestrel را عبور می‌داد. در مسیر برنامه، `Accept-Encoding` درخواست upstream خالی می‌شود و فشرده‌سازی یک‌بار با gzip سطح ۴ در nginx انجام می‌شود. در همان دادهٔ محلی، پاسخ gzip از **۱۰۰۶۴۵ به حدود ۷۲۳۷۸ بایت** رسید. زمان کل پاسخ HIT محلی از حدود ۱ms به حدود ۴ms تغییر کرد؛ هزینهٔ CPU این آزمایش چند میلی‌ثانیه است، نه اندازه‌گیری VPS یا ادعای حذف RTT شبکه. محتوای پاسخ برای gzip و identity، cache HIT، کوکی analytics و جلوگیری از کش خصوصی مستقلاً تست شد.
- برای تصویر استودیویی محصول در عرض ۴۲۰، مشتق مستقل `display-v2` با WebP کیفیت **۱۰۰** تولید می‌شود. **کیفیت ۱۰۰ به معنی lossless یا برابری تمام پیکسل‌ها نیست.** خروجی decode و با مرجع resize‌شده بررسی می‌شود: alpha باید دقیقاً برابر بماند؛ حداکثر اختلاف کانال قابل مشاهده ۱۶ از ۲۵۵ و میانگینِ وزن‌دار در ناحیهٔ قابل مشاهده حداکثر یک واحد از ۲۵۵ است. خروجی نامناسب به lossless برمی‌گردد. نامزد جدید فقط اگر تازه و کوچک‌تر باشد انتخاب می‌شود؛ فایل اصلی و مشتق‌های قبلی باقی می‌مانند. لوگوها و سایر اندازه‌های استودیو تحت این سیاست جدید قرار نمی‌گیرند.
- نمونهٔ محلی ۰۰۵۶: **۵۰۳۶۲ → ۲۱۸۸۴ بایت**؛ ۰۰۱۷: **۵۵۹۵۴ → ۲۴۴۴۰ بایت**. در مجموعهٔ واقعی، ۷۲ مشتق ساخته شد و ۵۶ مورد از بهترین گزینهٔ قبلی کوچک‌تر بودند. کنترل مستقل با libwebp/Pillow، برابری alpha و اختلاف رنگ را بررسی کرد؛ rounding بین decoderها ممکن است یک واحد تفاوت ایجاد کند. تمام **۲۴۲ فایل تصویر مخزن** در بستهٔ منتخب هش یکسان با منبع داشتند. فایل‌های تصویر بر اساس گزارش نام‌های کوتاه Waterfall به محصول مشخصی نسبت داده نشده‌اند؛ این دو شماره نمونهٔ واقعی مخزنند.
- نمایش سریع‌تر در مدل شبکه، پرش نورهای هیرو را آشکار کرد: ارتفاع stage با رسیدن نوار اعتماد از ۴۸۸ به حدود ۵۳۸px می‌رسید و تزئینات دارای موقعیت درصدی جابه‌جا می‌شدند. اکنون محتوای اصلی و نوار اعتماد پیش از لایه‌های تزئینی در HTML می‌آیند. همان گرادیان اصلی به‌عنوان زمینهٔ اولیهٔ stage قرار گرفته است. ترتیب نهایی لایه‌ها، عکس، متن، نور، آمار و انیمیشن حفظ شده؛ هیچ timer یا شرط تشخیص ابزار سنجش اضافه نشده است.

### موارد باز و مسیر پذیرش واقعی

- DOM و CSS مورد استفاده در حالت‌های دیگر برای حذف امتیازی محتوا دستکاری نشده‌اند. Structure واقعی تازه لازم است؛ به رسیدن آن به بالای ۹۵ نمرهٔ محلی نسبت نمی‌دهیم.
- برای مرورگر مدرن، HTTP/2 باید در اتصال مرورگر به nginx با TLS/ALPN فعال شود. `proxy_http_version` صرفاً مسیر nginx→Kestrel است. گواهی باید برای همان IP/دامنه معتبر باشد و URL عمومی برنامه، canonical و هدر forwarded scheme هماهنگ شوند. زنجیرهٔ ۳۰۷ پیش از تغییر باید از هدر واقعی تشخیص داده شود. CDN همراه دامنه/HTTPS مسیر کوتاه دیگری برای کاهش RTT است، اما اجباری‌بودن CDN برای Grade A از این گزارش ثابت نمی‌شود.
- تغییرات nginx باید همراه برنامه و مشتق‌ها منتشر شوند؛ انتشار صرف DLL تغییر فشرده‌سازی nginx را اعمال نمی‌کند. مسیر استاندارد `quick-republish.sh` تنظیم nginx و تولید مشتق‌ها را انجام می‌دهد. طبق محدودهٔ فعلی، روی VPS اعمالی انجام نشد.
- شبکهٔ runtime این محیط برای سایت و GTmetrix مجاز نشده است؛ پیش‌نویس ذخیره‌شده آن دو مقصد را دارد ولی نیازمند Save/Publish محیط است. نتیجهٔ فعلی قابل اعلام همچنان **B / ۷۹ / ۹۵ گزارش ارسالی** است. **پذیرش A و هر دو امتیاز بالاتر از ۹۵ باز مانده است.**

## ۱۳. نمایش زودتر هدر بدون تغییر طراحی

پس از `07f92ba`، استایل کوچک هدر در head قرار گرفت و **همان استایل کامل خانه، با ترتیب اصلی قواعد** بلافاصله پس از هدر و پیش از محتوای اصلی inline می‌شود. دانلود CSS خارجی یا تایمر فعال‌سازی وجود ندارد؛ صفحه بدون JavaScript هم استایل و ۸+۸ محصول دارد. قواعد هدر عمداً تکرار می‌شوند تا cascade عوض نشود. فایل جدید `critical-shell.css` با `npm run build` تولید می‌شود؛ نبود آن، مسیر قبلی استایل کامل head را فعال می‌کند.

هدر زودتر قابل مشاهده است؛ کلیک زودهنگام منو/سبد/ورود تا آماده‌شدن loader نگهداری و یک‌بار اجرا می‌شود. برای جلوگیری از جابه‌جایی عرض در مرورگر دارای اسکرول‌بار کلاسیک، فقط ریشهٔ خانه `overflow-y:scroll` دارد؛ چاپ `visible` است. آزمایش `scrollbar-gutter:stable` در حالت اسکرول‌بار مخفی ۱۵px از عرض کم کرد و کنار گذاشته شد. مقایسهٔ نهایی عرض/هندسه/فونت/رنگ در ۳۹۰/۷۶۸/۱۳۶۶ برابر مبناست؛ تست جداگانهٔ هدر با اسکرول‌بار کلاسیک و نگه‌داشتن ادامهٔ سند نیز پاس شد. بخش، تصویر یا انیمیشنی مخفی یا حذف نشده است.

### تغییرات منتخب

- **تفکیک CSS هدرِ `ea2ca6b` برگردانده شد.** استایل کامل خانه از ابتدا یک‌بار در head است؛ stylesheet دوم در body و فایل تولیدی `critical-shell.css` حذف شدند. فونت/keyframe دوباره ثبت نمی‌شوند. گرفتن و replay اولین کلیک حتی هنگام رسیدن تدریجی باقی سند حفظ شد. قفل اسکرول پس‌زمینه در منو/سبد/ورود/استوری و آزادشدنش پس از بستن نیز با wheel واقعی تست شد. ریشهٔ خانه فضای اسکرول‌بار کلاسیک را از ابتدا دارد و همان قفل‌های overlay را رعایت می‌کند؛ قاعدهٔ چاپ عادی حفظ شده است.
- اندازه‌گیری ویژگی‌ها و نوار هیرو از `ResizeObserver` می‌آید. ساخت انیمیشن نوار پیشرفت هم پس از چیدمان طبیعی انجام می‌شود؛ زمان ۶ثانیه‌ای، نقطه‌ها، swipe و افکت‌ها باقی‌اند. fallback مرورگر قدیمی حفظ شده است.
- `site.js` دیگر برای محاسبهٔ سرعت نوار، `scrollWidth` فوتر خارج صفحه را نمی‌خواند؛ این خواندن، رندر subtreeای را که CSS موجود قصد ردکردنش داشت اجبار می‌کرد. سرعت نوار و جای دکمهٔ تماس از اندازه‌های آمادهٔ observer محاسبه می‌شوند؛ clearance منوی پایین و فیلتر کاتالوگ در resize هم حفظ می‌شود.
- reveal خانه روی خود بخش‌ها فعال می‌شود، با اندازه‌گیری هم‌زمان کل سند و تغییر کلاس ریشه شروع نمی‌شود. اگر اسکریپت دیر برسد، بخش ازقبل دیده‌شده مخفی نمی‌شود؛ بخش‌های بعدی همان fade و stagger را هنگام scroll دارند. حالت بدون JS و reduced motion سالم است.
- سه لایهٔ Grid تو‌در‌توی قاب محصول به Flex و هم‌پوشانی absolute تبدیل شدند؛ عکس، قاب، gradient، سایه، blur، زمان‌بندی و چرخه حذف نشدند. مقایسهٔ هر ۱۶ کارت/قاب/تصویر در سه عرض، **۴۸ حالت**، اختلاف هندسه زیر ۱px و برابری تنظیم رنگ/سایه/فیلتر را تأیید کرد. اسکریپت `product-card-dual.js` تغییر نکرده است. هیچ فایل تصویر یا فونت مخزن تغییر نکرد.

در پروفایل محلی CPU کندتر، eager layout در راه‌اندازی اسکریپت‌ها بازتولید شد. تست جدید ثبت Layout هم‌زمان داخل initializerهای home/reveal/site را بررسی می‌کند؛ نسخهٔ نهایی صفر مورد داشت. این **صفر، TBT واقعی GTmetrix نیست**؛ مرورگر همچنان برای خود سند layout و paint انجام می‌دهد.
